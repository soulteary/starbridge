# MCP 并发与取消

每个 `starbridge serve` 进程最多同时执行 **4 个后端调用**，查询和写操作共用额度，超额调用排队。

- 排队时取消或超时，错误码分别为 `INTERRUPTED` / `TIMEOUT`，详情为 `phase:queued`、`outcome:no_result`，不会启动后端命令。
- 执行中的调用沿用后端的超时与取消处理。宿主 `--timeout` 从实际命令执行时计时；包含排队时间的截止时间由客户端设置。
- 同一 UUID 的启动、关机、挂起、恢复串行执行，不同 UUID 可并行。UUID 匹配忽略大小写和成对花括号。
- 开发模式的写动作沿用同一 VM 写锁，保守覆盖该 VM 的所有 guest 会话；诊断、快照列表和开发查询也使用同一调用额度。宿主文件动作另有覆盖预检查与执行的实例级串行锁。
- 名称写操作与所有其他写操作互斥；已有名称写操作排队时，新的 UUID 写操作也需等待。使用 UUID 可保留不同 VM 的并行能力。

读取不与写操作互斥，结果只代表查询时观察到的状态。

这些限制只作用于同一服务进程。多个 MCP 服务和独立 CLI 不共享锁；需要统一协调时，应通过同一个 MCP 实例访问。
