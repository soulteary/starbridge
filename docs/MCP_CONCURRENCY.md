# MCP 并发、会话锁与取消

每个 `starbridge serve` 进程最多同时占用 **4 个后端调用额度**，查询和写操作共享，额外调用排队。工作流、等待或传输等复合调用会在整个后端调用期间占用一个额度，不能据此假定同时运行 4 条 prlctl 子命令。

## 宿主协调

同一 UUID 的 VM 写操作和开发写操作串行，保守覆盖该 VM 的全部 guest 会话；UUID 匹配忽略大小写和成对花括号。不同 UUID 的写操作可并行，仍共用总额度。名称无法直接作为稳定锁标识，因此名称写操作与所有写操作互斥；已有名称写操作排队时，新的 UUID 写操作也等待。优先使用 UUID。

读取不与写操作互斥。诊断、快照列表、开发读取也使用总额度，查询结果只反映各自执行时的状态。后台任务、应用自身或用户操作仍可能改变状态。

宿主文件动作另有同实例串行锁，覆盖路径/profile 预检查和完整执行，避免这个实例的另一次文件写入替换刚检查的配置；见[workspace 规则](MCP_DEVELOPER.md#宿主工作目录)。其他进程的文件系统修改不受该锁控制。

## Windows UI 会话

UIA 操作、窗口聚焦/缩放、input.key/mouse/text 和视觉点击还使用 Windows 中按会话命名的 mutex。它协调安装了同一套 helper 的独立 worker，也包括由其他 MCP 实例或 CLI 发起的这些 UI 写操作；不锁定整个桌面、应用或其他输入来源。

ui.click 持有一次外层 lease，覆盖显式聚焦、校验、鼠标派发与后续截图，内部复用 UI 核心时不重复获取 mutex。普通 input.text 等入口自行获取同一个会话锁。等待锁超时可返回 SESSION_BUSY；发现此前 worker 异常离开持锁会话时返回 SESSION_RECOVERY_REQUIRED，先观察实际状态。

这些 guest UI 锁不统一协调 VM 电源、文件传输或具名后台任务。宿主的 VM 写锁和 4 个额度只属于同一服务进程；多个 MCP 实例、独立 CLI 不共享这些宿主锁。

## 截止时间与未知结果

客户端截止时间包括排队时间；宿主全局 `--timeout` 主要约束实际命令执行，不能当成整个工作流总期限。等待和截图等动作还各有自身预算，应给客户端足够时间完成整条操作链。

排队期间取消/超时分别返回 INTERRUPTED / TIMEOUT，详情为 `phase:"queued", outcome:"no_result"`，不会开始后端命令。进入后端后的超时、取消和输出限制沿用具体动作契约；宿主停止等待不保证 guest 工作已结束。

UI worker 在启动前拒绝时可报告 not_started；聚焦、文本或鼠标输入可能已开始后失败则为 unknown。ui.click 和 input.text 提交后的响应/图片校验失败也保留 unknown。不得据此自动重试写动作；先通过新观察、task.status、文件哈希或工作流检查点核实。`dispatched`、关闭请求 accepted 和 MCP `isError:false` 都不替代业务后置条件。
