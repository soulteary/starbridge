# MCP 并发与取消

每个 `starbridge serve` 进程最多同时执行 4 个后端调用，包括 VM 查询、guest 查询与 VM 生命周期操作。达到上限的调用排队；客户端取消或截止时间到达时，排队调用返回 `INTERRUPTED` / `TIMEOUT`，附带 `phase:queued`、`outcome:no_result`，不会启动后端命令。正在执行的调用仍沿用后端的超时与取消处理。宿主 `--timeout` 从实际执行命令时开始计时，客户端可另行设置包含排队时间的调用截止时间。

生命周期写操作另有目标协调：同一 UUID 的 start、stop、suspend、resume 串行，不同 UUID 可以并行，仍受总并发上限约束。UUID 不区分大小写，带或不带花括号视为同一个标识。

名称可能变化，也可能与某个 UUID 指向同一台 VM。因此以名称发起的写操作与所有其他写操作互斥；等待中的名称写操作会阻止新 UUID 写操作进入，避免持续请求让它一直排队。推荐使用 UUID，以保留不同 VM 的并行能力。读取操作不与写操作互斥，返回的是查询时观察到的状态。

这些限制仅覆盖同一 MCP 服务实例，不是跨进程的 VM 租约。普通 CLI 每个进程只执行一次命令；分别启动的 CLI 或多个 MCP 服务不共享锁。需要跨进程协调的调用方应统一通过一个服务实例访问。
